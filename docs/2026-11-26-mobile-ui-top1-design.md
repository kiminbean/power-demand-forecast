## 0. 결론 한 쪽

1. **기반 시안 C(비전문가용 안내형, "5초 안에 읽히는 제주 전력시장")**. 심사 3인 모두 1위(3/3). 2위는 B 2표, A 1표. 보르다(2·1·0점) C 6 · B 2 · A 1. 심사 예측 평균 C 8.43 · B 8.25 · A 8.08.
2. 모든 화면은 **답 문장 → 숫자 하나와 상태 칩 → 출처와 KST 시각** 순서로 연다. 근거(산출 방식·용어)는 한 번 눌러 여는 시트에 둔다.
3. 탭 4개: **오늘 · 입찰 · 정산 · 알아보기**. 정산·발전소 자료는 공개되지 않으므로 지어낸 값 대신 "공개 데모에서 제공하지 않습니다" 제한 카드와 ┆예시┆ 표시가 붙은 예시를 보여 준다.
4. A에서 접목: 수급 균형 식과 범위 막대(예비율 15 % 경계 표시, round 1 D9에서 "관심 경계" 낱말을 뺐다), 지금 시각 pill과 지연·끊김 단계(60분 넘으면 판정 철회), 시간 선택 스텝퍼, 출처와 기준 시각 표(`/realtime-status` 응답 상태 포함), 오프라인 띠, 시간대 요약.
5. B에서 접목: 앱 안 테마 선택(시스템·밝게·어둡게), `Example<T>` 브랜드 타입과 픽스처 재생 테스트, UI 금지 검사, RN-web 의미 탐침, 차트 키보드 탐색, 입찰 계산기 503 처리, 하루전 마감 상태표, 5단계 글자 크기, 라우터 세부 규칙.
6. 심사 필수 수정 30여 건을 모두 반영했다(부록 A에 위치 표). 특히 **기존 node 테스트 35개를 한 줄도 고치지 않는다**: 헤더는 `App.tsx` 안의 훅 없는 `Header` 함수로 남기고 `eXeco`·`v6.1`을 계속 보인다.
7. 이번 세션에서 확인한 새 사실 두 가지가 설계를 바꿨다.
   - Metro 최소화기는 한글을 `\uXXXX`로 바꿔 **한 글자에 6바이트**를 쓴다(운영 번들에 3,907개). 그래서 긴 설명 글(용어 사전·둘러보기·산출 방식)은 번들 대신 `mobile/public/content/guide.ko.json`에 두고 필요할 때 읽는다.
   - KPI 기상은 기상청 **초단기실황**(`getUltraSrtNcst`, `api/realtime_api.py` 72행)이다. API 문자열의 "(기상청 단기예보)"는 이름표 오류다. 실패하면 API가 출처 표시 없이 5.0 °C·3.0 m/s·60 %·맑음을 보낸다(`api/v6_routes.py` 433–464행). 이 값은 "기본값 · 실측 아님"으로 표시한다.
8. 예상 첫 평가: 평균 **8.6**, 항목 최저 R8 8.2(15절). 가장 큰 위험은 M9(압축 없이 Slow 4G 6.0초)다. 번들 한도 640,000 B를 단계마다 잰다.

## 1. 목표와 합격선

### 1.1 루브릭 (TOP1 기준선)

- 항목: R1 시각 완성도 · R2 정보 위계와 첫 화면 · R3 차트 · R4 신뢰·출처 · R5 테마 · R6 모바일 사용성·반응형 · R7 접근성 · R8 구현 품질. 기준 정의(앵커와 측정법)는 `scratchpad/mobile/research/MOBILE_COMPETITORS.md` 6절이다.

## 2. 확정 결정

### 2.1 고정 제약 (워크플로가 정한 것)

1. Expo + react-native-web 유지, `npx expo export --platform web`, `public_server.py` 변경 금지.
2. 새 npm 의존성 금지(`node_modules`가 git에 들어 있어 추가 하나가 수천 파일을 바꾼다). `package.json`의 기존 패키지(`react-native-svg` 등)는 번들 비용만큼 값을 할 때 쓴다. `package.json`은 `scripts`만 고친다.
3. 공개 데이터는 허용 목록 GET뿐: `/health`, `/api/v1/health`, `/api/v1/smp-forecast`, `/api/v1/market-status`, `/api/v1/dashboard/kpis`, `/api/v1/bidding/optimized-segments`, `/api/v1/model/info`, `/api/v1/smp/current`, `/api/v1/smp/day-ahead`, `/api/v1/power-supply`, `/api/v1/realtime-status`, `/smp/rtm/model/info`, `/smp/rtm/predict`, `/api/v1/resources`. 정산·발전소 엔드포인트는 공개가 아니다.
4. 정직성은 게이트다. 모든 값은 상태와 KST 시각 또는 출처를 가진다. "지금" 표시는 실제 시계의 KST로 정한다. 시장 논리는 기기 시간대에 기대지 않는다. 정확도는 문서화된 수치만 쓴다.
5. 파일 삭제 금지(삭제는 사용자 승인 필요). 쓰지 않는 코드는 저장소에 남기되 번들에서 빠지게 한다. 이름 바꾸기도 삭제로 본다.
6. 다크 모드는 OS(`prefers-color-scheme`)를 따르고 데이터 색은 두 테마에서 같다.
7. 대시보드 개편의 교훈: 모든 폭(320/360/390/430/768/1280)과 모든 스크롤 컨테이너를 잰다. 상호작용 상태를 하나씩 따로 훑는다. 화면에 보이는 값은 포맷 도우미 하나를 거친다. 변경은 검토할 수 있는 크기로 나눈다.

### 3.2 기준 경로(base) 감지 (빌드 플래그 없음)

1. `document.querySelector('script[src*="_expo/static/js/web/"]')`의 `src`에서 `_expo/` 앞부분이 기준 경로다. multiplex에서는 `public_server.py` 146–148행이 `/mobile/_expo/…`로 바꿔 주므로 `/mobile/`, 단일 앱 모드(:10004, :10105)에서는 `/`.
2. 못 찾으면: `pathname === '/mobile'` 또는 `pathname.startsWith('/mobile/')`일 때 `/mobile/`, 아니면 `/`. (`startsWith('/mobile')`만 쓰면 `/mobile-x`도 걸린다.)
3. `/mobile`(끝 슬래시 없음)은 `replaceState`로 `/mobile/`로 고친다.
4. 순수 함수 `parseLocation(pathname, search, base)`·`buildUrl(state, base)`·`detectBase(scriptSrc, pathname)`는 `mobile/src/app/routes.ts`(DOM 없음)에 두고 node 테스트로 고정한다(`/mobile/`, `/`, `/mobile`, `/mobile-x`, 깊은 경로, 모르는 쿼리).

- 입찰 계산 호출: `GET /api/v1/bidding/optimized-segments?capacity_mw=50&risk_level={conservative|moderate|aggressive}`(서버 검증값 그대로). 한 번에 하나만(single-flight), 성향별 5분 캐시, **자동 폴링 없음**. 스텝퍼는 캐시된 `hourly_bids`(24시간이 한 응답에 있다)를 읽고 새로 요청하지 않는다. 성향을 바꿀 때만 요청한다. 503(서버가 동시 1건만 허용)은 1.5초 뒤 **한 번만** 자동 재시도, 그래도 503이면 "다른 요청을 처리하는 중입니다 · 잠시 뒤 [다시 계산]". 400은 "계산 조건 오류"(정상 경로에서는 생기지 않음). 응답의 `trading_date`가 `/market-status`의 `dam.trading_date`와 다르거나 그사이 `forecast_date`가 바뀌면 오래된 입력으로 보고 한 번 다시 계산한다(스켈레톤 유지).
- LadderChart(round 1 D12): x = 누적 물량 0–50 MW(구간당 5 MW), y = 가격 0부터(원/kWh, 맨 위 눈금은 50 단위 올림, 기준선·띠도 담는다), 계단은 채우지 않고 ▨ 추정 칩과 같은 빗금 + `borderStrong` 1.5 px 외곽선(10개 단색 자홍 막대가 한 덩어리로 읽혔고 자홍은 오늘 차트의 예측 색이었다), 그 시간 기준선(계산기 입력 q50)은 자홍 점선, q10–q90은 옅은 띠(8 % + 1 px 테두리, 대체값이면 없음), 고른 구간만 `primary`로 채운다. 각 계단 위에 낙찰 가능성 % 글자(12 px), 단위 줄 오른쪽에 "계단 위 % = 낙찰 가능성(추정)"(round 2: 같은 그림을 계단 한 이름으로). 360 미만에서는 1·4·7·10구간 글자만 보이고 표에는 전부 있다. **불투명도로 확률을 나타내지 않는다.** 차트 위 범례(12 `text2`)는 기호 + 이름 한 줄(round 2 F14, `ui/charts/ChartFrame`의 `ChartKey`): [파선] "기준선 205.9원" · [띠] "80% 구간 175.2–239.3원" · [빗금 계단] "입찰 가격(추정)". 계단을 누르거나 ←/→로 고르면 차트 아래 판독 칩(`well`) "4구간 · 5 MW · 134.5원 · 낙찰 가능성 62% (추정)"(위에 두면 처음 고를 때 누른 차트가 밀린다). 끝 x 눈금("50 MW")은 라벨 상자 오른쪽 끝에 flex로 붙인다(`alignItems: flex-end`, 첫 눈금은 `flex-start`): WCAG 1.4.12 글자 간격에서 틀 안쪽으로 자란다. `textAlign: right`만으로는 상자보다 길어진 글자가 오른쪽으로 넘쳐(넘치는 줄은 시작 쪽 정렬) 틀 밖 4 px가 잘렸다(F13b 측정).

### 6.3 데이터 계층

- `src/data/client.ts`: 허용 목록 중 **쓰는 것만** 감싼다. 메서드 이름은 옛 `api.ts`와 같게: `getDayAheadSMP()` · `getSMPForecast()` · `getModelInfo()` · `getDashboardKPIs()` · `getPowerSupply()` · `getMarketStatus()` · `getOptimizedSegments(risk)` · `getRealtimeStatus()`. 기준 URL은 `src/config/environment.ts` 규칙(웹은 같은 출처 상대 경로)을 그대로 쓴다. GET에 `Content-Type`을 붙이지 않는다. **`console.*`를 쓰지 않는다**(처리한 실패는 상태로 보여 준다). 응답은 `types.ts`의 모양 검사기를 통과해야 하고, 틀리면 `ApiShapeError`로 실패한다(조용히 0이나 기본값으로 바꾸지 않는다). 옛 `src/services/api.ts`는 가져오지 않는다(형식 `import type`만 허용).
- `src/lib/resource.ts`(`useResource`, 약 120줄): 키별 `{data, fetchedAt, status, error}`. 처음 마운트, 새로고침 버튼, 화면이 보일 때 5분마다(`document.visibilityState === 'visible'`), 숨었다 보이면 5분 넘은 것만. `AbortController` 10초. 네트워크 오류·502·503에만 1.5초 뒤 1회 재시도, 4xx는 재시도 없음. 실패해도 마지막 좋은 값은 남기고 지연으로 표시. 같은 키는 한 번에 하나만 요청(중복 제거).
- 오늘의 첫 로드 요청: `day-ahead` · `smp-forecast` · `model/info` · `dashboard/kpis` · `power-supply` · `market-status`(시계 차이용, 작음). 입찰: `market-status` · `smp-forecast`(가격 근거 줄, round 1 D5) · `optimized-segments`. 알아보기 › 출처와 출처 시트: `realtime-status` + 이번 방문에 아직 없는 `day-ahead` · `smp-forecast` · `dashboard/kpis` · `power-supply` · `market-status`(D15, 입찰 계산은 부르지 않는다). 정산·알아보기 첫 화면: 없음. 같은 키는 저장소가 한 번만 보낸다(오늘에서 넘어오면 다시 보내지 않는다).

### 7.2 타입으로 막기

- `Provenanced<T> = { value: T; unit: Unit; state: 'confirmed' | 'measured' | 'forecast' | 'estimated' | 'default' | 'national'; source: string; time: { kind: '거래시간' | '조회' | '관측' | '만든 시각' | '서버 시각' | '평가 기간'; kst: string }; note?: string }`에 `adapters.ts` 안에서만 만들 수 있는 브랜드(내보내지 않는 `unique symbol`)를 붙인다. `Value`·`KpiBlock`·`HeroValue`·차트는 이 타입만 받는다. 칩 없는 숫자는 컴파일 오류다.
- `Example<T>`는 `examples.ts`에서만 만들 수 있는 다른 브랜드다. `SampleValue`와 `SampleRibbon` 아래 컴포넌트만 받는다. 두 브랜드는 서로 바꿔 넣을 수 없다.
- 예시 용량(50 MW)에 기대는 값(구간 물량, 기대 수입)은 `Example`이다. 용량과 무관한 계산기 값(구간 가격, 낙찰 가능성)은 `Provenanced`(추정)이다.

**공급능력 `supplyPair(kpis, powerSupply)`** — `powerSupply.data`에서 `hour === powerSupply.current_hour`인 행을 찾고, 그 행의 `demand`가 `kpis.current_demand_mw`와 **±1 MW 안**이고 수요가 ③이며, `powerSupply.data_source`가 그 행을 실시간 값으로 맞췄다고 말할 때(`scaled to real-time: … supply N MW`, N이 그 행 `supply`와 ±1 MW, round 2 integrity: 크롤러가 수요만 주면 지금 시각 행의 수요는 KPI와 맞아도 공급은 EPSIS 30일 평균 그대로였다)만 그 행의 `supply`를 실측 공급능력으로 쓴다. 아니면 "공급능력 미수신". 다른 시각 행은 쓰지 않는다. 예비율 경계 = 공급능력 ÷ 1.15(예비율 15 %가 되는 수요, 화면 "수요 1,036 MW · 넘으면 예비율 15% 미만"), 예비력 = 공급능력 − 수요(반올림은 표시할 때 1회).

**예비율 단계 `reserveLevel(r)`** — 대시보드 7.4절의 경계값과 판정 문장, 단계 이름은 모바일만 다르다(round 1 D9): ≥ 15 «정상 · 넉넉합니다», < 15 «보통 · 여유가 15% 아래입니다»(round 2 F14: 값 하나로는 추세를 말하지 않는다, 대시보드는 보고서 후속), < 10 «낮음 · 여유가 부족합니다», < 5 «위험 · 공급이 빠듯합니다». KPX 공식 경보 단계 낱말(준비·관심·주의·경계·심각)을 쓰지 않는다(`provenance.test`). 단계 판정은 ③일 때만, 60분 끊김이면 멈춘다("새 자료를 받지 못해 예비율 단계 판정을 멈췄습니다").

**기상 `weatherProvenance(kpis)`** — 대시보드 `_fmt_weather_provenance`:
- `data_source`에 `KMA Weather (파일)` → `file`: `[▨ 추정 · 실시간 아님]`, "기상청 과거 자료 24시간 평균 (API 서버) · 실시간 아님"
- `KMA Weather Crawler` · `KMA Real-time API` · `기상청 (실시간)` 중 하나 → `live`: `(● 실측)`, "기상청 초단기실황 (API 서버)", "관측 시각 미제공 · 조회 HH:MM KST"
- `kpis`가 객체인데 위 둘 다 없음 → `default`: `[▨ 기본값 · 실측 아님]`, "API 서버 기본값 (실측 아님)"(API가 5.0 °C · 3.0 m/s · 60 % · 맑음을 출처 없이 보낸 경우)
- `kpis`가 객체가 아님 → `none`: 날씨 줄 숨김

**SMP 예측 종류 `smpForecastKind(fc)`** — `model_used`에 "기준선"·"전날 같은 시간"·"어제 같은 시각"·"naive"·"baseline" 중 하나 → `baseline`(`[┅ 예측 · 기준선]`, 문서화 정확도 표시). 알려진 학습 모델 이름(대시보드 설계 1196행 목록) → `model`(`[┅ 예측 · 학습 모델]`, 정확도 "등록되어 있지 않습니다", 이름은 산출 방식 시트에 API 문자열 그대로, 끝의 " · 검증 MAPE x%"만 뗀다). 그 밖 → `fallback`(`[▨ 추정 · API 대체값 (모델 예측 아님)]`, 점선, 띠 없음). F3에서 `src/smp/models/serving.py`와 `api/v6_routes.py`의 대체 경로 문자열을 읽어 목록을 테스트로 고정한다. 모르면 닫힌 쪽(추정)으로 둔다.

### 7.5 KST 시계와 "지금"

- `kstNow() = Date.now() + skewMs`. KST 날짜·시각은 `new Date(kstNow() + 9 h)`를 `getUTCFullYear/Month/Date/Hours/Minutes/Day`로 읽어 얻는다. `Intl` 시간대·`getHours()`·`toLocaleTimeString()`·`toISOString().split('T')` 금지(7.10절).
- API의 오프셋 없는 시각(`market-status.current_time`, `created_at`, `realtime-status.timestamp`)은 KST로 본다: `Date.UTC(y, m−1, d, hh, mm, ss) − 9 h`. 오프셋이 있으면 그것을 따른다. `new Date(문자열)` 금지.
- 지금 거래시간 = KST 시 + 1(1–24). 06:03:57 → 7(`07h · 06–07시`) = API `trade_hour` 7.
- 차트 지금선 x = (KST 시 + 분/60)/24 × 그림 폭, `forecast_date`가 KST 오늘일 때만. 라벨 `지금 06:04`.
- `/market-status`가 하루전 개장·마감의 기준이다. 기기 시계는 응답 사이의 카운트다운만 움직인다.
- 테스트: `TZ=UTC`, `TZ=Asia/Seoul`, `TZ=America/Los_Angeles`에서 같은 순간(2026-11-26 06:03:57 KST, 09:59:30 KST, 10:00:30 KST, 23:59:30 KST)으로 영웅 거래시간·카운트다운·지금선 위치·마감 상태·NowPill 글자가 모두 같아야 한다(node, 하위 프로세스마다 `TZ=`). 브라우저에서는 Playwright `timezone_id` 3개로 같은 비교(11절).

- 회색 "API 표기" 줄은 산출 방식 시트(`today-accuracy`)의 "이번 화면의 값"에만 둔다: "API 표기: 검증 MAPE {mape}% (최근 N일 재현 · 문서 수치와 기간이 다릅니다)", "API 표기: 80% 구간 적중률 {coverage}% (마지막 N일 보류 검증) · 10번 중 {round(coverage/10)}번꼴로 실제 가격이 띠 안에 들었습니다". 기간 글자(N)는 `/model/info`의 `data_source`("최근 150일 재현 MAPE · … 마지막 30일 보류 검증")에서 읽고 `version === 'baseline-24h'`일 때만 붙인다. 다른 버전은 기간 없이 숫자와 "API 설명: {data_source}"를, 수치가 없으면 "API 표기: 검증 수치 없음"을 쓴다(round 1 integrity: 기간 글자를 굳혀 두면 다른 버전에서 틀린다). 시트 설명 글이 walk-forward·보류 검증을 한 줄씩 풀어 쓴다(JSON).
- 문서화 수치는 `smpForecastKind = baseline`일 때만. 금지: "신뢰도", R²=0.95, BiLSTM·CatBoost 수치, `/smp/rtm` 수치, v4.1의 16.82 %(평가 기준이 달라 나란히 쓰지 않는다).

### 7.8 실행 중 일관성 검사 (각각 픽스처 단위 테스트)

1. **비교 문장·확정 가격 점**: `normalized(dayAhead.trade_day) === forecast.forecast_date`이고 `q50[trade_hour − 1]`이 유한하며 0.00 입력이 아닐 때만. 아니면 PriceCard는 자기 사실만.
2. **입찰 가격 근거 공개 줄**: `optimized.trading_date !== forecast.forecast_date`이고 보이는 시간의 `|hourly_bids[h].smp_forecast.q50 − forecast.q50[h]| ≤ 0.05`이면 "가격 근거: {forecast_date} 기준선(={전날} 확정 가격) · 거래일 {trading_date}와 하루 차이"(alert 아이콘 + 글자). 백엔드가 D+1 기준선을 주면(P5) 저절로 사라진다. 예측은 입찰 화면이 직접 받는다(round 1 D5). 받지 못하면(값도 없음) "가격 근거 확인 전 · 서버 기준선 예측 사용 · 거래일 {trading_date}"이고, 받는 중이면 줄이 없다.
3. **모델 문자열**은 그 시리즈를 그린 같은 `/smp-forecast` 응답의 `model_used`에서 가져온다(`/model/info`에서 가져오지 않는다). 끝의 " · 검증 MAPE x%"는 떼어 보인다: API 정확도는 "API 표기" 줄에만(I5, round 1 D8).
4. **0.00 입력 시간**: `q50 === 0`인 시간은 선을 끊고 중립 빗금 열 + 라벨 "기준선 입력 0.00 · 예측 아님"(한 번), 표 "— (입력 0.00)", 판독 줄 "기준선 입력 0.00 · 예측 아님", 최고·최저·평균·시간대 요약에서 빼고 "0.00 입력 N시간 제외". 띠도 그리지 않는다(대시보드 13.2·14.2 J3).
5. **단위**: API `price_krw_mwh`에는 원/kWh 값이 들어 있다(118.1은 kWh당). `expected_revenue`는 천 원 단위다. 두 변환은 `format.ts`에만 있고 스냅숏으로 테스트한다(구간 1 · 0h → 56.1만원, 19h 합계 → 468.6만원).
6. **계산기 시간 번호**: `hourly_bids[i].hour`는 0부터, 거래시간 = `hour + 1`. `hourly_bids[i].smp_forecast.q50 === forecast.q50[i]`(소수 첫째 자리)로 테스트한다.

RN-web `SafeAreaView`(네 방향 모두 `env()` 패딩)는 쓰지 않는다.

### 8.4 테마 (OS 따름 + 앱 안 선택)

- `src/app/theme.tsx`: `mode` ∈ `system`(기본) · `light` · `dark`를 localStorage `pd-theme`에서 읽는다(try/catch, 실패하면 `system`). `scheme = mode === 'system' ? useColorScheme() : mode`. RN-web의 `useColorScheme`은 `prefers-color-scheme` 변화를 바로 따른다.
- 고르면: `document.documentElement`의 `data-theme` 설정(시스템이면 제거), `style.colorScheme`, 두 theme-color 메타의 `content`를 고른 `canvas`로(시스템이면 원래 값으로 되돌림) 바꾼다(`head.web.ts`). OS 변화는 `system`일 때만 반영한다. 다시 방문했을 때 번들이 뜨기 전에도 같은 값이도록 `index.html` 머리 테마 script가 저장한 `light`·`dark`로 두 메타를 먼저 바꾼다(F13c, 8.1절).
- 레이아웃은 두 테마에서 같고, 데이터 색은 바뀌지 않는다.

### 8.5 제목과 언어

`head.web.ts`(약 30줄)가 라우트별 `document.title`과 theme-color를 맡는다. `head.ts`(네이티브·테스트)는 아무것도 하지 않는다. `<html lang="ko">`는 템플릿에 고정한다.

## 13. 배포 절차 (평가 통과 + P1 승인 뒤에만)

조건: round N 평가에서 모든 R ≥ 8.0 · 평균 ≥ 8.5 · M1–M9 · I1–I5 통과, 평가한 export의 sha256 기록, 사용자 승인(P1). 서버 재시작은 필요 없다(`public_server.py`가 요청마다 디스크에서 읽는다). 아무것도 지우지 않는다.

```zsh
LIVE=/Users/ibkim/.local/share/power-demand-public/mobile
EXP=$SM/build/runs/<평가한 단계 태그>/export
STAMP=$(date +%Y%m%d-%H%M%S); BK=$LIVE.backup-top1-$STAMP
NEW=$(basename $EXP/_expo/static/js/web/AppEntry-*.js)

# 0) 사전 확인: 평가한 바로 그 번들인가
shasum -a 256 $EXP/_expo/static/js/web/$NEW          # 평가 기록의 sha와 같아야 한다
# 1) 백업: 날짜 붙은 형제 폴더로 복사 (기존 관례 mobile.backup-<tag>-<stamp>)
cp -pR "$LIVE" "$BK" && diff -rq "$LIVE" "$BK" && echo BACKUP_OK
# 2) 새 export 복사 (--delete 없음: 옛 번들 파일은 참조 없이 남는다)
rsync -a "$EXP/" "$LIVE/"
# 3) 확인 (앱 정보의 앱 갱신일 APP_UPDATED_AT(src/content/strings.ts, round 2에서 "화면 갱신" → "앱 갱신")은 평가에 넘길 번들을 만들기 전에 그 빌드 날짜로 맞춘다. 평가 뒤에 고치면 sha가 달라져 0)이 깨진다)
curl -s http://127.0.0.1:10005/mobile/ | grep -c "src=\"/mobile/_expo/static/js/web/$NEW\""     # 1
curl -s http://127.0.0.1:10005/mobile/ | grep -c 'lang="ko"'                                      # 1
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' http://127.0.0.1:10005/mobile/_expo/static/js/web/$NEW
cmp $EXP/_expo/static/js/web/$NEW $LIVE/_expo/static/js/web/$NEW && echo SAME
for p in bidding settlement guide content/guide.ko.json; do curl -s -o /dev/null -w "$p %{http_code}\n" http://127.0.0.1:10005/mobile/$p; done   # 모두 200
PD_BASE=http://127.0.0.1:10005/mobile/ PD_OUT=$SM/eval/deploy-$STAMP $PY -I $SM/eval/tools_v2/sweep.py grid   # 콘솔 오류 0, 게이트 재확인
zsh $SM/eval/tools_v2/run_gate_checks_v2.sh http://127.0.0.1:10005/mobile/
# 공개 주소(Funnel :10000의 /mobile/)를 휴대폰에서 열어 오늘·입찰·정산·알아보기를 한 번씩 확인한다
# 4) 되돌리기 (문제가 있으면 바로)
rsync -a "$BK/" "$LIVE/" && curl -s http://127.0.0.1:10005/mobile/ | grep -o 'AppEntry-[0-9a-f]*\.js'   # 옛 해시
```

되돌린 뒤 새 번들과 `content/guide.ko.json`은 참조 없이 남는다(삭제는 승인 사항). 배포 사실(백업 폴더 이름, sha, 시각)을 `PROJECT_STATUS.md`에 적는다.
