# 제주 전력 예측 모델 경쟁 비교 분석

- 작성일: 2026-11-06
- 대상: 전력수요 LSTM(1시간 앞), 제주 하루전 SMP 예측, 태양광 발전량 예측(RE-BMS 서빙)
- 방법:
  - 운영기관·국내외 기업·논문·대회의 공개 수치를 조사했다. 1차 조사 83건과 보완 조사(4개 레인) 45건, 모두 128건의 주장을 원문으로 검증했다(검증 107, 부분 검증 19, 미검증 2).
  - 같은 데이터로 기준선을 다시 계산했다.
  - 결론을 좌우하는 수치는 별도 스크립트로 재현했다. 스크립트는 `docs/benchmark-2026-11-06/`에 있다. 수요 LSTM의 정정 수치는 `compare_demand_retrain.py`가 만든다(아래 정정 참고).
- 원 질문: "경쟁 업체들의 MAPE와 R²를 조사하고, 내 모델이 더 좋은지 나쁜지 검토하고 비교 분석해 달라"

> **정정 (2026-11-06, 근거: `docs/2026-11-06-demand-retrain-raw-target.md` 2절)**
>
> - 이 보고서의 수요 LSTM "원본 목표" 수치는 2026-11-05 학습 때 저장된 예측을 원본 실측으로 다시 채점한 것이다. 그 예측은 잘린 입력(694.66 MWh 상한)으로 만들어졌다. 운영 체크포인트에 잘린 입력을 넣으면 그 예측이 그대로 재현된다.
> - 실제 API는 원본 수요를 입력한다. 같은 추론 경로로 다시 재서 아래 수치를 고쳤다.
>   - 고정 test: 4.31% / R² 0.926 / MAE 21.2 → **4.16% / R² 0.939 / MAE 20.0**
>   - 2024년 하반기: 4.92% / R² 0.922 → 4.51% / R² 0.947
>   - 잘린 631시간: "평균 53 MWh 과소 예측" → bias −5.9 MWh
> - 결론은 그대로다. 서빙 모델은 여전히 시간대별 선형 AR과 7일 ramp보다 유의하게 나쁘다(DM +14.21, +5.30).
> - `verify_ar.py`의 LSTM 수치(4.307%)는 저장된 예측을 채점한 값이다. 서빙 경로 수치는 `compare_demand_retrain.py`가 만든다.

## 2. 비교 전에 알아야 할 다섯 가지

1. **목표가 다르다.**
   - 우리 수요 목표는 KPX 제주 "전력거래량"(시장 거래분)이다. KPX와 논문 대부분은 "계통수요"(발전단 수요)를 예측한다.
   - 거래량은 대략 계통수요에서 HVDC 육지 수입과 약 21 MW를 뺀 값이다. HVDC는 2024년 공급의 29.6%였다.
   - 실측 계통수요를 거래량으로 나눈 비율은 2024년 하반기 중앙값 1.50이다. KPX 실시간 예측(jlfdRt)으로 나누면 중앙값 1.45, 시간대별 1.27~1.63이다.
   - 같은 선형 AR로 재면 계통수요 MAPE는 1.05%, 거래량은 3.75%다. MAE로는 2.3배 차이다.
   - 따라서 거래량은 구조적으로 더 어려운 목표이고, 다른 목표의 헤드라인 MAPE와 순위를 매길 수 없다.
2. **예측 시점이 다르다.** 우리 수요 모델은 1시간 앞이다. 경쟁자는 대부분 하루 앞(day-ahead)이다.
3. **R²는 목표의 분산에 좌우된다.**
   - 거래량에서는 persistence만으로 R² 0.90, AR로 0.95가 나온다.
   - 계통수요에서는 0.94~0.99가 나온다.
   - 다른 시리즈의 R²끼리는 비교할 수 없다. 조사한 운영기관(KPX, PJM, ERCOT, NYISO, ISO-NE, CAISO) 중 수요 R²를 공개하는 곳은 없었다.
4. **지표 정의가 다르다.**
   - 수요는 MAPE를 쓴다.
   - SMP는 0원 근처 가격 때문에 MAPE가 불안정해서 MAE와 naive 대비 MAE 비율을 쓴다. 우리 MAPE는 |가격|>10원인 시간만 계산한다.
   - 발전량은 설비용량 대비 오차(KPX 규칙)를 쓴다.
5. **집계 방식이 다르다.** 분할별 평균과 전체(pooled) 계산 값이 다르다. 예: SMP naive의 R²는 분할 평균 0.20, pooled 0.34다.

비교 등급:

| 등급 | 의미 | 예 |
|---|---|---|
| T1 직접 비교 | 같은 시장·같은 목표 | SMP의 vpp-capstone, VOLTA |
| T2 같은 지역·다른 목표 | 제주이지만 목표가 다름 | KPX 계통수요 예측, 제주 수요 논문 |
| T3 다른 계통·같은 과제 | 다른 나라나 다른 계통 | 미국 ISO, 섬 계통, 유럽 가격 예측 |
| T4 참고·마케팅 | 정의 불명 또는 검증 불가 | 업체 홍보 수치, 누수 있는 프로토콜 |

## 3. 전력수요 예측

### 3.1 정직한 성능 수치: 기존 보고값 4.03%는 외부에 쓰면 안 된다

학습 데이터 `data/processed/jeju_hourly_merged.csv`는 수요를 694.658 MWh에서 잘라낸다(clip).

- 이 상한은 2013~2024 **전체** 기간의 Q3+1.5×IQR과 정확히 일치한다. 전체 기간에는 test가 포함되므로 test 정보가 누수된다. 그 결과 실제 여름 피크가 지워졌다.
- 잘린 시간은 919개이고 모두 하향 절단이다. 연도별로 2019년 3, 2020년 16, 2021년 40, 2022년 206, 2023년 151, 2024년 503개다.
- 원인은 `src/data/preprocessing.py`의 `handle_outliers`다. 전체 데이터에 IQR 클리핑을 적용한다.

| 고정 test 2023-07~2024-12 (13,200시간) | 잘린 목표 (기존 보고) | 원본 목표 (정직한 값) |
|---|---|---|
| LSTM demand_only (서빙 중) | 4.03% / R² 0.937 | **4.16% / R² 0.939**, MAE 20.0 MWh |
| LSTM weather_full | 4.14% / R² 0.933 | 4.26% / R² 0.936 |
| persistence (t−1) | 5.12% | 5.28% / R² 0.902, MAE 25.4 |

- 원본 목표 열의 LSTM은 운영 체크포인트를 API 추론 경로로 원본 수요에 돌린 값이다(정정 전: 4.31% / 0.926, 4.41% / 0.924).
- 잘린 631개 test 시간에서 서빙 모델의 bias는 −5.9 MWh다(persistence −9.5). 정정 전의 "평균 53 MWh 과소 예측"은 잘린 입력 때문에 생긴 착오였다.
- 예측이 "직전 값 + 보정량"이라 원본 입력이 들어가면 피크도 따라간다.
- 클리핑의 해는 주로 평가(누수된 헤드라인)와 학습 데이터 왜곡에 있었다. 서빙 정확도에 준 영향은 작다. 원본으로 재학습하면 demand_only는 4.17%로 그대로이고, weather_full은 4.26%에서 4.21%로 조금 좋아진다.

### 3.2 결정적 비교: 단순 선형 모델에 진다

비교 대상은 24개 시간대마다 따로 적합한 선형 회귀 AR이다. 입력은 시차 1, 2, 24, 25, 48, 168, 169와 요일이고, 휴일·기상·HVDC는 넣지 않았다.

고정 test, 원본 목표:

| 모델 | MAPE | R² | MAE (MWh) |
|---|---|---|---|
| 시간대별 선형 AR (2019~2022 학습) | **3.75%** | **0.951** | 17.9 |
| 시간대별 선형 AR (2013~2022 학습) | 3.78% | 0.950 | 18.0 |
| 7일 ramp persistence (파라미터 없음) | 4.00% | 0.945 | 19.1 |
| LSTM (서빙 중, 서빙 경로) | 4.16% | 0.939 | 20.0 |
| persistence | 5.28% | 0.902 | 25.4 |

**Diebold-Mariano 검정** (Newey-West 24 lag, 양수면 LSTM이 나쁨)

- 서빙 경로: LSTM 대 AR(2013~2022 학습) +14.21, LSTM 대 ramp7 +5.30이다(`compare_demand_retrain_out.json`). 정정 전 값은 각각 +10.65(AR 2019~2022 학습), +6.22였다.
- 잘린 입력·목표: 각각 +15.78, +4.27이다.
- 모두 유의하게 LSTM이 나쁘다.

walk-forward는 잘린 목표로만 비교했다. LSTM의 fold별 예측이 저장되지 않아 원본 목표로 다시 계산할 수 없기 때문이다. AR은 2013-01-01부터 (시험 연도−1)-06-30까지 학습했다. LSTM의 학습 종료 시점과 같다.

| 시험 연도 | LSTM | AR | 7일 ramp | persistence |
|---|---|---|---|---|
| 2021 | 3.49% | 3.37% | 3.45% | 4.27% |
| 2022 | 3.31% | 3.17% | 3.39% | 4.13% |
| 2023 | 3.45% | 3.25% | 3.44% | 4.35% |
| 2024 | 4.20% | 3.87% | 4.11% | 5.20% |
| 평균 | 3.61% | **3.42%** | 3.60% | 4.49% |

- AR이 4개 연도 모두 이긴다. 평균 R²는 AR 0.943, LSTM 0.935다.
- 정정 전 고정 test 수치는 세 번 계산했다(워크플로 에이전트 2개와 별도 스크립트 `verify_ar.py`). 그러나 세 계산 모두 저장된(잘린 입력) 예측을 채점했다. 정정 후 LSTM 수치는 `compare_demand_retrain.py`의 서빙 경로 계산 한 번이다. 정정 후 수치는 별도 검증 에이전트가 독립적으로 다시 계산해 일치를 확인했다.
- walk-forward는 학습 창이 다른 두 계산에서 모두 AR이 4개 연도를 이겼다. 하나는 위의 확장 창이고, 다른 하나는 워크플로의 이동 4년 창(AR 평균 3.40%)이다.
- LSTM(서빙 경로)과 AR(2019~2022 학습)을 50:50으로 섞으면 3.84%(원본 목표)로 AR 단독보다 나쁘다. 정정 전 워크플로 계산은 저장된 예측으로 3.89%였다.

### 3.3 경쟁자 수치 (모두 T2 이하, 같은 목표의 경쟁자 없음)

KCI, DBpia, RISS, KIEE, KSNRE, MDPI, IEEE, Wiley, arXiv와 KPX 문서, 공공데이터포털, 기업 보도자료를 찾았지만 "KPX 제주 전력거래량"을 예측한 연구·운영기관·업체는 없었다. 후보였던 Moon·Ahn·Lee(2023)는 원문 Table 1 평균이 671 MW다. 같은 기간 거래량 평균은 461 MWh이므로 계통수요를 쓴 것이다.

KPX 하루전 예측의 실력은 D-1 16:00에 알 수 있는 실측만 쓰는 naive와 비교해야 공정하다. 이 기준에서 KPX의 MAE 개선폭은 2024H2에 −4~+7%, 2023-09~2025-04에 +11~+21%다.

### 3.4 난이도 보정

각 모델의 MAPE를 "같은 시리즈에서 같은 AR의 MAPE"로 나누었다.

- 박해수(2022, 계통수요): 약 1.04배
- 우리 LSTM: walk-forward 1.04~1.09배, 고정 test 1.10배 (잘린 목표 대 잘린 목표)

비율은 비슷하지만 실력이 같다는 뜻은 아니다. 계통수요에서는 AR이 이미 집계 하한(약 1%) 근처라 더 개선할 여지가 적다. 거래량은 HVDC 흐름이나 KPX 예측 같은 외생 변수로 개선할 여지가 더 클 수 있다.

## 5. 태양광 발전량 예측

### 5.1 "R²=0.95" 표기의 실체

`api/v6_routes.py:783`은 대시보드에 "Renewable ML: GradientBoosting (R²=0.95)"를 표시한다. `verify_solar.py`로 확인한 결과는 다음과 같다.

- 서빙 모델은 **무작위로 섞은 80/20 분할**(random_state=42)로 학습됐다. 모델의 초기 상수 39.4257이 그 분할의 학습 평균과 정확히 일치한다. 무작위 분할이라 5.2절 holdout 기간 행의 약 80%가 학습에 들어갔다. 따라서 5.2절 평가는 서빙 모델에 유리하게 치우쳐 있다.
- 스케일러는 test를 포함한 **전체 54,113행**으로 fit됐다(`n_samples_seen_` = 54,113).
- R² 0.95류 수치는 **측정 일사량**을 입력으로 쓴 평가다. 서빙 시점에는 측정 일사량이 없다. 시간순 분할로 같은 조건을 재현하면 R² 0.90, KPX 오차율 8.4%다.
- 실제 서빙 경로는 다음과 같다.
  - 현재 기온과 습도만 사용한다.
  - 습도로 구름량을 추정한다.
  - 사인 곡선으로 일사량을 추정한다.
  - 실제 설비용량과 상관없이 446 MW로 고정한다.
  - 기상 예보는 쓰지 않는다.

### 5.2 KPX 규칙 평가 (holdout 2022-12-10~2024-05-28, 421일)

KPX 오차율 = |예측 − 실측| / 설비용량 × 100이다. 이용률 10% 이상인 시간만 계산한다. 측정 일사량 행을 제외한 모든 방법은 D-1 10:00 발행 기준이다.

| 방법 | KPX 오차율 | R² (전체 시간) | 월 평균 ≤10% 통과 |
|---|---|---|---|
| 측정 일사량 사용 (예측 시점에는 불가능, 참고용) | 8.4% | 0.90 | 13/17개월 |
| **월×시간 기후값** | **12.5%** | 0.71 | 1/17 |
| 깨끗한 재학습 + 같은 서빙 방식 (실제 설비용량) | 14.4% | 0.60 | 1/17 |
| 서빙 모델 + 실제 설비용량 | 14.5% | 0.52 | 1/17 |
| persistence (D-2 같은 시각) | 16.3% | 0.48 | 0/17 |
| **서빙 모델 그대로** | **17.0%** | **0.41** | **0/17** |

서빙 예측은 기후값(12.5%)보다 나쁘다. KPX 등록 시험(월 평균 ≤10%)은 한 달도 통과하지 못한다. 실제 설비용량을 쓰면 서빙 모델(14.5%)과 누수 없이 다시 학습한 모델(14.4%)이 거의 같다. 문제의 핵심은 학습 누수보다 서빙 설계(예보 미사용, 습도로 구름량 추정, 용량 고정)에 있다.

### 5.3 경쟁·제도 기준 (설비용량 대비 오차)

| 출처 | 수치 | 성격 |
|---|---|---|
| KPX 정산 인센티브 (2025년 중반부터) | ≤4%: 4원/kWh<br>4~6%: 3원/kWh<br>6% 초과: 없음 | 전력시장운영규칙 |

- 섬 전체 집계(약 420 MW)는 개별 자원보다 예측이 쉬운 편이다. 그런데도 우리 서빙 예측은 시장 평균(5.7%)보다 약 3배 나쁘다.

- 경쟁사 수치는 자원이나 포트폴리오 단위이고, 대부분 자체 보고다.
- 우리 데이터에는 출력제한 시간 표시가 없어 그 시간을 그대로 포함했다. KPX는 이 시간을 제외하므로, 여기서는 모든 방법의 오차가 다소 커진다.

## 7. 권고안

**우선순위 높음**

1. **수요 목표 클리핑 중단**
   - `handle_outliers`의 전체 데이터 IQR 클리핑을 없애거나, 같은 파일의 학습 구간 전용 클리핑 클래스로 바꾼다.

   - 외부에는 원본 기준 수치(현재 4.16% / 0.939, 서빙 경로)를 보고한다.

   - persistence, 7일 ramp, 시간대별 AR(휴일 추가)을 넣는다.

3. **태양광 예측 개선**
   - "R²=0.95" 라벨을 제거한다.
   - 시간순 분할과 학습 구간 전용 스케일러로 다시 학습한다.
   - 이용률을 예측하고 현재 설비용량을 곱한다. 시간순으로 학습하면 학습 구간의 최대 용량이 368 MW라서, 트리 모델이 그보다 큰 용량을 외삽하지 못한다.

   - KPX 규칙으로 평가한다.

## 8. 한계

- **수요 비교의 한계**
  - 같은 목표의 경쟁자가 없어 "더 좋다/나쁘다"를 직접 판정할 수 없다.
  - AR은 휴일·기상·HVDC가 없는 낮은 기준선이다. 튜닝된 모델이라면 LSTM을 더 큰 차이로 이길 가능성이 높다.
  - LSTM의 walk-forward 예측이 저장되지 않아 fold 비교는 잘린 목표 기준이다.
- **KPX 수치의 한계**
  - KPX 예측 정확도는 우리가 공개 데이터로 도출한 값이다. KPX는 정의된 제주 정확도를 공개하지 않는다. 정의가 없는 두 수치("3.75 → 2.48", "6% → 2%")만 있다.
  - jlfd와 jlfdRt는 실측 계통수요보다 약 21 MW 낮게 나오는 정의상 편차가 있다.
  - KPX 시범사업 데이터(2024-07~)와 우리 거래량 실측(~2024-12)은 6개월만 겹친다.
- **출처 검증 상태**
  - 부분 검증: 박해수 논문, VOLTA, 현대자동차 WaveNet, epftoolbox·Uniejewski의 naive 대비 비율(조사 에이전트가 계산), KPX 예측 정확도(공개 데이터로 도출, 2024H2 값은 두 에이전트가 재현).
  - 단일 계산(재검증 안 함): KPX 13:00·16:00·휴일 규칙 naive, VOLTA 구간의 naive.
  - 태양광 평가는 워크플로와 `verify_solar.py`가 따로 계산했고 결과가 일치했다.
  - Jang 외 2024(1.10%)는 미검증이라 결론에 쓰지 않았다.
  - 학술 결과 상당수가 관측 기상(ex post)을 쓰거나, test로 설정을 고르거나, 기준선을 보고하지 않는다.
  - 업체 수치는 자체 보고다.
- **태양광 평가의 한계**
  - 동서발전 파일을 제주 시장 태양광으로 가정했다. 설비용량이 445~450 MW로 KPX와 일치한다.
  - 출력제한 시간은 제외하지 않았다.
  - 풍력은 평가하지 못했다.

## 9. 재현 방법

```bash
# 저장소 루트에서 실행
.venv/bin/python docs/benchmark-2026-11-06/verify_ar.py     # 수요: 상한 절단 확인, LSTM vs AR/ramp7/persistence, DM 검정 (LSTM은 저장된 잘린 입력 예측, 정정 전 수치)
.venv/bin/python docs/benchmark-2026-11-06/compare_demand_retrain.py  # 수요: 서빙 경로로 운영 LSTM 재채점 (정정 후 수치, 먼저 diagnose_ar_residual.py 실행)
.venv/bin/python docs/benchmark-2026-11-06/verify_smp.py    # SMP: naive vs 혼합 규칙
.venv/bin/python docs/benchmark-2026-11-06/verify_solar.py  # 태양광: 서빙 모델 출처, KPX 규칙 평가
```

- 결과는 같은 폴더의 `*_out.json`에 저장된다.
- `verify_smp.py`는 KPX 시범사업 API 원자료 `data/raw/kpx_jeju_pilot_raw_2024-07-02_2026-11-04.csv`가 필요하다. 이 파일은 로컬에만 있다(data/raw는 git 제외).
- KPX 하루전 예측 4.67%(2024H2), 계통수요 AR 1.05%, 11:00 발행 naive 4.887%는 워크플로 에이전트 두 개가 별도 코드로 재현했다. 이 계산 스크립트(계통수요 다운로드 포함)와 문헌 조사 원자료는 세션 임시 폴더에만 있어 보존되지 않는다.
